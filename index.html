Help

How this works

Every day

Logging something you ate

Tap Add an item, start typing the name, and pick from the list if it comes up — the label fills itself in and folds away to a summary line. Then enter how much you had and tap the chevron at the top of the card to save and collapse it.

For something new, fill in whatever the package tells you. Nothing is required. Missing values show as a dash and are skipped in the totals, so a food with only calories still works.

Serving size versus quantity

The serving size is what the label's numbers refer to — "per 100 g". The quantity is what you actually ate. The app divides one by the other, so if the label says 389 kcal per 100 g and you had 80 g, you get 311.

If either is missing the item still saves; it just contributes nothing to the totals until you fill in both.

Correcting a label

Open the item, expand the nutrition label, and change what's wrong. Saving writes the correction back to the shared catalog and updates any other entry of the same food on today's log.

Reset saved label empties the numbers but keeps the name. Delete from catalog removes the food entirely and takes its entries off today's log with it.

Days and history

Start a new day, or clear the day?

Start a new day is the one you want each morning. It files today's totals and weight into your history, then empties the list. The individual items aren't kept — only the day's summary.

Clear today's entries throws the day away without recording it. Use it when you've been experimenting rather than eating.

Both need a second tap to confirm.

The app says my log is still on an earlier day

That's the prompt at the top reminding you that yesterday never got closed. Tap Start a new day and those totals go into your history under the correct date.

If you'd rather keep adding to it — a late night that ran past midnight — tap Keep adding to it. It stays quiet until you next open the app.

Recording your weight

Open the menu with the gear icon and type it into the Weight box. Pounds by default; the kg button switches the display. Weight is always stored in pounds behind the scenes, so switching units never alters your history.

Whatever is entered when you start a new day gets filed with that day. Weighing every day isn't necessary — gaps are fine and the chart simply joins across them.

Reading the chart

Tap Chart beside Recent days. Calories are the green bars on the left axis, weight is the amber line on the right, and the dashed line is your calorie target if you've set one.

Drag sideways to pan. Pinch on a phone, or scroll with a mouse, to zoom. Tap a day to pin its numbers at the top; tap empty space to unpin. The 7d / 30d / 90d / All buttons jump to a range.

The weight axis scales to whatever is on screen, which is why a two-pound change looks dramatic when zoomed in. That's deliberate — it's the only way small changes are visible at all.

Units and targets

Both live in the gear menu. Each nutrient has its own unit buttons and its own daily target; set a target and a percentage appears on the summary bar.

Targets and units persist across days and never reset on their own. Targets are stored in the unit you typed them in, so switching from grams to ounces re-displays them rather than changing them.

Codes, tokens and people

Changing your code

Gear menu → Change your code. Type six digits and tap Change code. The device you're on switches immediately.

It then shows a var VAULT = ... line. Copy it, paste it over the matching line near the top of index.html, and commit — that's what makes your other devices accept the new code. Until you do, this device uses the new code and the others still use the old one.

A code already used by someone else is refused.

It says the token was rejected

The GitHub token has expired or been revoked. No data is lost — everything lives as files in the private repo, and the app keeps working from its local copy, so carry on logging.

  1. On GitHub: Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
  2. Repository access: only the data repo. Permissions: Contents → Read and write.
  3. Open setup.html locally, paste the new token, re-enter everyone's names and codes, and Generate.
  4. Paste the new VAULT line into index.html and commit it.

Once the app reloads with the new line, anything you logged in the meantime syncs up.

Adding another person

Run setup.html again with the same token and repo. Add a row for the new person with their own name and 6-digit code, and keep the existing rows exactly as they are so nobody's code changes. Generate, then commit the new VAULT line.

They get their own log file and their own targets. The food catalog is shared with everyone.

Nobody remembers a code

There's no recovery — that's what makes the encryption worth anything. Run setup.html again with a fresh code for that person and commit the new line.

Their history is safe: it lives in the data repo under their log file, and the new code opens the same file as long as you keep the same order of people in the setup page.

Syncing and data

What the status line at the bottom means

Saved — everything is on GitHub. Saving… — a commit is queued; saves are batched to roughly one every eight seconds rather than one per keystroke.

Offline or cannot reach GitHub — you can keep logging. It's held on the device and pushed when the connection returns.

Two devices, or two people at once

Each person's log is a separate file, so those never collide. The catalog is shared, and if two people edit the same food the most recent edit wins.

The app refreshes the catalog when you open it and when you return to the tab. Refresh now in the menu forces it.

Getting back something you deleted

Every save is a commit, so the data repo holds the full history. Open the repo on GitHub, click catalog.json, then History, and look at any earlier version.

To restore, copy the values out of the old version and re-enter them in the app. Reverting the file directly on GitHub also works, but the app may overwrite it if it has newer edits pending.

Keeping the repo small

Every save is a commit, so the data repo grows steadily. admin.html — kept on your own machine, not published — shows the repo size against a ceiling you set, lists every file, and can trim archived days, prune deleted foods, take a backup, and squash the git history when it gets large.

Once a year is plenty for two people.

Where everything is kept

Your food catalog and each person's log are JSON files in your private GitHub repo. The app itself is a single HTML file on GitHub Pages. Nothing goes to any other service.

Your access token is encrypted inside the app file with your 6-digit code, and only ever decrypted in your browser's memory. The code is remembered on the device so you don't retype it; Lock the ledger forgets it.
